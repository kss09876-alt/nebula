# NEBULA 유료화 구성 (초안)

지금 상태: **결제 꺼짐** (`js/config.js` → `paywall.enabled: false`). 모든 전시는 무료로 열려 있고, 앱 '마이 → 멤버십'은 가격과 '준비 중' 안내만 보여 줍니다.

## 구조
```
관람객 ── 로그인(Supabase Auth: 애플·구글·카카오)
   │
   ├─ 앱 결제: 애플·구글 인앱결제 ── RevenueCat ──┐
   ├─ 웹 결제: 토스페이먼츠/포트원 ───────────────┤ 웹훅
   │                                              ▼
   │                               서버(Supabase) 구매 기록 `entitlements`
   ▼
전시 열기 → 서버에 '볼 수 있나?' 확인 → 유료 전시 뒷부분 전달
```

## 이미 만들어 둔 것 (웹)
- `js/membership.js` — 상품·가격(원화/달러), 멤버십 화면, 구매·복원 버튼, 전시 잠금(무료 앞부분 + 안내), 4개 언어
- `js/cell.js` — 유료 전시는 구매 전 `previewBlocks`개 블록만 보여 주고 잠금 블록 표시
- `terms.html`, `privacy.html` — 이용약관·개인정보처리방침 **초안** (법률 검토 필요)
- `docs/paid/schema.sql` — 서버 표 설계, `docs/paid/webhook.ts` — 결제 알림을 받아 구매 기록에 적는 함수 뼈대

## 시험해 보기 (실제 결제 아님)
- 앱: `app.html?paytest=1` → 마이 → 멤버십
- 전시 잠금: `cell.html?id=c004&paytest=1&paid=c004`
- 시험 구매는 이 기기에만 저장되고, 멤버십 화면의 '테스트 구매 지우기'로 지웁니다.

## 실제로 켜려면
1. **권리**: 유료로 팔 전시의 작가·권리자 계약(해외 온라인 판매 포함). 계약 전 전시는 `paid`로 지정하지 않기.
2. **사업자**: 사업자등록, 통신판매업 신고, 애플·구글 개발자 계정, 애플 소규모 개발자 할인 신청.
3. **서버**: Supabase 프로젝트 생성 → `schema.sql` 실행 → 로그인 제공자 설정 → `webhook.ts` 배포.
4. **결제**: RevenueCat에 상품 등록(`nebula.member.monthly`, `nebula.member.yearly`, `nebula.pass.day`(하루 입장권, 소모성)), 웹 결제 대행사 가입.
5. **연결**: `membership.js`의 `setProvider()`에 서버 구현을 끼움(구매 기록 조회·구매·복원).
6. **전시 파일 보호**: 지금은 전시 내용이 공개 주소에 있어 화면 잠금만으로는 완전히 막을 수 없음. 유료 전시의 본문(blocks)은 서버가 구매 확인 뒤에만 내려 주도록 옮기기.
7. **호스팅**: GitHub Pages → 자체 도메인 + Cloudflare Pages 등으로 이전, 앱 `server.url` 변경.
8. `paywall.enabled: true`, 유료 전시 지정(`paywall.paid` 또는 시트 cells의 `paid` 칸).

## 스토어 심사에 필요한 것
구매 복원 버튼(있음) · 계정 삭제 · 애플 로그인(다른 소셜 로그인을 넣을 때) · 약관·개인정보처리방침 링크(있음) · 구독 자동 갱신·해지 안내(있음) · 웹을 감싸기만 한 앱으로 보이지 않도록 앱 고유 기능(인앱결제·알림·센서).

## 수수료를 줄이는 방법
애플 소규모 개발자 할인 신청(15%) · 웹 결제 병행(앱 안에서는 웹 결제를 안내·링크하지 않기) · 앱 가격을 웹보다 조금 높게 · 단체·오프라인 판매.
