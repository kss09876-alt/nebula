# NEBULA 전시 만들기 — 5단계 플로우

새 전시(행성)를 만들 때 이 순서를 따른다. 단계마다 **산출물**을 남기고, 소유자 확인을 받은 뒤 다음 단계로 넘어간다.

```
1. 작가 분석  →  2. 전시 기획서  →  3. 인터랙션 구상  →  4. 대중성 디벨롭  →  5. 프로토타입
  (이야기·방향)     (발표 자료)       (센서·체험 설계)     (쉽게·와닿게)        (실제 페이지)
```

| 단계 | 하는 일 | 산출물 | 넘어가는 조건 |
|---|---|---|---|
| 1 작가 분석 | 작가·작품을 조사해 핵심 이야기와 방향을 찾음 | `01-작가분석.md` | 한 문장 메시지 확정 |
| 2 전시 기획서 | 제목·구성·관람 흐름을 발표용으로 정리 | 기획서 슬라이드 | 소유자·작가 동의 |
| 3 인터랙션 구상 | 장면마다 '무엇을 하게 할지' 설계 | `03-인터랙션.md` | 장면별 조작 1개 이상 |
| 4 대중성 디벨롭 | 처음 보는 사람 기준으로 다듬기 | `04-디벨롭.md` | 점검표 통과 |
| 5 프로토타입 | NEBULA에 실제 전시 페이지 제작 | PR + 미리보기 주소 | 시험 점검표 통과 |

각 단계 양식은 `templates/` 폴더에 있다. 새 전시는 `docs/exhibitions/<전시 id>-<이름>/` 폴더를 만들고 양식을 복사해 채운다.

---

## 0. 시작 전 확인 (권리)

**권리부터 확인한다.** 지난 전시에서 배운 것:
- 실제 작가·단체 이름을 쓰면 그쪽 동의가 있어야 한다. 동의 전이면 '기획 제안 프로토타입, 협의 전'이라고 화면에 밝히고, 로고·공식 문구를 쓰지 않는다 (예: N-004 산사).
- 실존 인물을 다루는 가상 기획전은 '권리자와 관계없음'을 표기하고 유료로 팔지 않는다 (예: N-004 async).
- 원곡 음원·영상은 허락 없이 넣지 않는다. 소리는 직접 합성하거나 허락받은 파일만.
- 실제 사건·희생을 다루면 윤리 기준을 먼저 정한다 (예: N-003 빛쌀 — 폭력 재현 금지, 수치·출처 고정).

| 항목 | 상태 |
|---|---|
| 작가·권리자 동의 | 받음 / 협의 중 / 가상 기획 |
| 작품 이미지·영상 사용 범위 (국내/해외, 무료/유료) | |
| 실제 사건·인물 포함 여부 → 윤리 기준 필요 | |

## 1. 작가 분석 — 이야기와 방향 찾기

작가의 작업 전체를 보고 **이 전시가 관람객에게 남길 한 가지**를 찾는다.

- **작가**: 활동, 대표작, 자주 쓰는 재료·형식, 반복되는 주제
- **작품**: 이번에 다룰 작품, 만든 배경, 작가의 말
- **핵심 이야기**: 작품 속에 숨은 '사람의 이야기'는 무엇인가 (빛쌀 → 순이 한 사람의 이야기)
- **방향성**: 이 작가가 지금 어디로 가고 있나, 왜 지금 이 전시인가
- **한 문장 메시지**: "이 전시를 보고 나면 ○○를 느낀다"
- **감각 키워드**: 이 작업을 손으로 만진다면 어떤 동작일까 (쌓다, 흩어지다, 기다리다, 어긋나다…)

양식: `templates/01-작가분석.md`

## 2. 전시 기획서 — 발표 자료

작가·협력처·투자자에게 보여 줄 수 있는 슬라이드로 만든다 (NEBULA의 Slides로 제작, 필요하면 PowerPoint·PDF로 내보내기).

권장 구성 (10~14장):
1. 표지 — 전시 제목, 부제, 작가
2. 한 문장 메시지
3. 작가 소개와 작업 세계
4. 왜 지금, 왜 온라인인가
5. 관람 흐름 — 장면 순서 (PART 1 이야기 → PART 2 작품과 기록 같은 큰 줄기)
6. 장면별 개요 (장면 이름 · 이야기 · 체험 한 줄)
7. 대표 인터랙션 2~3개 (그림·흐름도)
8. 소리·화면 분위기 (색, 질감, 사운드)
9. 대상 관람객과 언어 (한·영·중·일)
10. 일정 · 필요한 것 (작품 자료, 권리, 감수)
11. 운영 방식 (무료/유료, 기간, 월간 호 편성)

## 3. 인터랙션 구상 — 무엇을 하게 할 것인가

원칙: **조작이 이야기의 뜻을 몸으로 느끼게 해야 한다.** 재미만 있는 조작은 빼고, 장면의 감정과 이어지는 동작을 고른다.

- 빛쌀: 쌀독을 흔들어 털수록 쌀이 줄어듦 → 굶주림 / 폰을 가만히 들고 기다리면 새벽 → 기다림
- async: 일곱 추가 점점 어긋남 → '맞추지 않는다' / 폰을 엎으면 고요

장면마다 한 줄로 정리한다:

| 장면 | 이야기(감정) | 휴대폰 동작 | PC 대체 | 결과(화면·소리) | 끌 조건 |
|---|---|---|---|---|---|

### 쓸 수 있는 동작 (`js/sensors.js`)
기울이기(`tiltX/tiltY`) · 흔들기(`onShake`) · 돌리기(`onSpin`) · 엎어 두기(`onFaceDown`) · 나침반(`heading`) · 후 불기(`onBlow`, 마이크) · 카메라 AR(`startCamera`) · 위치(`getPosition`) · 진동(`vibrate`, 안드로이드) · 누르기·길게 누르기·문지르기·여러 손가락 · 가만히 있기(움직임 없음 감지)

### 이미 있는 블록 (재사용 우선, `js/cell.js`·`js/sakamoto-lab.js`)
cover · text · quote · image · gallery · video · sticky · timeline · wave · cosmos(워프) · quantum · prism · shadow · soundmap · listen(마이크) · piano · async · rain · forest · silence · chapter · records · memory
→ 맞는 블록이 있으면 구글 시트(blocks)에 행만 추가해 만든다. 없을 때만 새 블록이나 단독 페이지(빛쌀·산사처럼)를 만든다.

### 지켜야 할 것
- 모든 체험은 **PC(마우스·키보드)로도** 할 수 있어야 한다.
- 센서 권한 없이도 **끝까지 볼 수 있어야** 한다 (버튼 대체).
- 센서·마이크·카메라·위치 데이터는 기기 안에서만 쓰고 저장·전송하지 않는다 (화면에 안내).
- 슬픔·희생을 다루는 장면에서는 흔들기 같은 가벼운 조작을 끄고, 묵념(엎어 두기) 같은 조용한 동작만 둔다.

양식: `templates/03-인터랙션.md`

## 4. 대중성 디벨롭 — 처음 보는 사람 기준으로

전시를 모르는 사람이 휴대폰으로 3분 안에 빠져드는지 본다.

점검표 (`templates/04-디벨롭.md`):
- [ ] 첫 화면 10초 안에 '무엇을 보는지, 무엇을 하면 되는지' 알 수 있다
- [ ] 이야기가 먼저, 설명·기록은 뒤에 (빛쌀 1부 이야기 → 2부 기록 구조)
- [ ] 인물·장면이 있다 (추상적 설명보다 한 사람의 이야기)
- [ ] 문장이 짧다 (카드 한 장 3~5문장)
- [ ] 조작 안내가 그 장면에 바로 뜬다 (휴대폰 안내 칩)
- [ ] 끝에 남는 한 장면·한 문장이 있다
- [ ] 외국인이 배경을 몰라도 이해된다 (영어판 배경 설명 한 줄)
- [ ] 작가가 원래 말하려던 것과 어긋나지 않았다 (작가 확인)

가능하면 주변 사람 3명에게 보여 주고, 어디서 멈추고 어디서 헤맸는지 적는다.

## 5. 프로토타입 — NEBULA에 만들기

1. **데이터**: `data/cells.json`(또는 구글 시트 cells)에 전시 한 줄 — id, 제목, 부제, 작가, 기간, 색, `fx`/`planet`(행성 모양), `month`(월간 호), `url`(단독 페이지일 때).
2. **블록**: 구글 시트 blocks(또는 `cells.json` blocks)에 장면 순서대로. 새 체험 블록은 `extra: true`로 저장소에 넣을 수 있다.
3. **단독 페이지**가 필요하면 `<이름>.html` + `js/<이름>.js` + `css/<이름>.css` (빛쌀·산사 방식).
4. **번역**: 한·영·중·일. 본문은 `data/i18n.json`, 화면 문구는 `js/i18n-dict.js` 또는 페이지 안 번역표.
5. **소리**: Web Audio 합성. iPhone 무음 스위치·앱 전환 대응(`sansa.js`·`bitssal-sound.js` 참고).
6. **월간 호**: `data/issues.json`에 편성, 관련 유튜브·기사 링크.
7. **캐시**: 바꾼 JS/CSS는 `?v=N`을 HTML과 import 양쪽에서 올린다.
8. **작업 안내서**: `CLAUDE.md` 구조표에 새 파일과 규칙을 추가.

### 시험 점검표
- [ ] 휴대폰(작은 화면 iPhone SE 크기 포함)·PC에서 오류 없음
- [ ] 4개 언어에서 글이 겹치거나 넘치지 않음
- [ ] 센서 권한을 거부해도 끝까지 볼 수 있음
- [ ] 소리: 첫 탭 뒤 재생, 화면 밖·앱 전환 시 멈춤
- [ ] 앱 안(착륙 → iframe)에서도 열림
- [ ] 느린 휴대폰(CPU 4배 느리게)에서 멈춤이 길지 않음
- [ ] 권리·윤리 표기가 화면에 있음
- [ ] PR로 올리고 미리보기 주소와 화면 캡처를 소유자에게 전달

## 지난 전시에서 배운 것

| 전시 | 배운 점 |
|---|---|
| N-001 최초의 방 | 방을 나누기보다 하나로 이어진 흐름이 낫다 (빛줄기로 장면 연결) |
| N-003 빛쌀 | 기록보다 한 사람의 이야기가 와닿는다. 이야기는 앞, 작품·기록은 뒤. 가상 인물임을 밝힌다 |
| N-004 async | 작가의 실제 작업 방식(양동이 빗소리, 현장 녹음)을 체험으로 바꾸면 설명 없이 전달된다 |
| N-004 산사 | 실제 단체와 협업을 '가정'할 때는 협의 전임을 분명히 적는다 |
