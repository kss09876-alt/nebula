# 컬렉트 (온라인 아트 판매)

앱 탭 **컬렉트**. Artsy를 참고해 넣은 것:

- **작품 둘러보기:** 종류(회화·종이·조각·설치·사진·판화)·가격대·정렬·구매 가능만 거르기
- **이번 주 추천 작품**, **작가 줄**(팔로우)
- **작품 상세:** 크기(cm·in), 재료, 에디션 남은 수, 보증서·액자·발송지, 가격(또는 '가격 문의'), 상태(구매 가능·예약 중·판매 완료), 관련 전시로 가기, 같은 작가의 다른 작품
- **작품 저장(하트)**, **작가 팔로우**, **구매 문의 / 가격 제안**
- **마이 → 나의 컬렉트:** 저장한 작품·팔로우한 작가·문의한 작품

저장·팔로우·문의 기록은 이 기기에만 남는다(`nebula-shop-*`).

## 작품 넣는 법

1. cells 시트(`1hezkf…`)에 탭을 두 개 만든다. 탭 이름은 **artworks**, **artists**.
2. 첫 줄에 아래 칸 이름을 적는다. `work_id`·`artist_id` 칸이 있어야 시트로 인식한다. 없으면 `data/artworks.json`을 쓴다.
3. 실제 작품이 들어가면 `js/config.js`의 `shop.showSamples`를 `false`로 바꾼다. 그러면 예시 작품이 사라진다.

**artworks**

| 칸 | 내용 |
|---|---|
| `work_id` | 고유 번호 (예: w001) |
| `artist` | 작가 `artist_id` |
| `title`, `title_en` (`title_zh`, `title_ja`) | 제목 |
| `year` | 제작 연도 |
| `medium` | painting / work-on-paper / sculpture / installation / photography / print |
| `material`, `material_en` | 재료 |
| `w`, `h`, `d` | 크기(cm) |
| `edition`, `edition_left` | 에디션 총수·남은 수 |
| `price_krw`, `price_usd` | 가격. 둘 다 비우거나 `price_request`=1이면 '가격 문의' |
| `status` | available / reserved / sold |
| `certificate`, `frame`, `offer`, `featured` | 1이면 보증서 있음·액자 포함·가격 제안 받음·추천 |
| `ships_from`, `ships_from_en` | 발송지 |
| `image` | 드라이브 파일 주소 또는 id |
| `cell` | 관련 전시 id (예: c005) |
| `desc`, `desc_en` | 작품 설명 |

**artists**: `artist_id`, `name`, `name_en`, `born`, `base`, `base_en`, `bio`, `bio_en`

## 구매(일반 결제) — 토스페이먼츠 결제창

실물 작품이라 **애플·구글 인앱결제 대상이 아니에요**. 그래서 앱 안에서도 카드 결제를 받을 수 있어요(App Store 가이드라인 3.1.3(e)). 수수료는 PG 수수료만 내요.

흐름:
1. 작품 상세에서 **구매하기**를 누르면 받는 분·주소·필수 동의를 입력해요(국내 배송만, 해외는 문의).
2. 서버 `create-order`가 작품을 30분 동안 잡아 두고, **금액을 서버 표에서 계산**해 주문번호와 함께 돌려줘요.
3. 토스 결제창이 열려요. 성공하면 `checkout.html`로 돌아와요.
4. 서버 `confirm-payment`가 주문 금액과 같은지 확인한 뒤, 토스 승인 API를 시크릿 키로 불러요.
5. 작품은 **판매 완료**, 주문은 **결제 완료**가 돼요. 실패하면 작품 예약이 풀려요.
6. 주문에는 **어느 전시에서 샀는지(`cell_id`)**가 남아요. 전시별 판매와 작가 정산에 써요.

전시 연결:
- 작품에 `cell`(전시 id)을 넣으면 앱의 전시 상세에 **'이 전시의 작품'**이 떠요.
- 작품 상세에는 **'관련 전시 보기'**가 떠요.

파일:
| 파일 | 하는 일 |
|---|---|
| `js/shop-pay.js` | 화면 쪽 결제 흐름(주문 만들기 → 토스 SDK → 승인), 시험 모드 |
| `checkout.html` + `js/checkout.js` | 결제창에서 돌아오는 페이지(성공·실패·확인 실패), 앱으로 돌아가면 주문 내역이 열림 |
| `docs/shop/schema.sql` | `works`·`orders` 표, 작품 잡아 두기 `hold_work()`, 풀기 `release_holds()` |
| `docs/shop/create-order.ts`, `confirm-payment.ts` | Supabase Edge Function 뼈대 |

켜는 순서:
1. 사업자 등록 → **통신판매업 신고**
2. 토스페이먼츠 가입·심사(미술품 판매 업종)
3. Supabase에 `schema.sql` 실행, 함수 두 개 배포
   - 환경 변수: `TOSS_SECRET_KEY`, `ALLOW_ORIGIN`
4. 작품을 `works` 표와 시트에 같은 `work_id`로 넣기
5. `config.js`에 다음 값을 넣기:
   - `shop.pay.clientKey`(`test_ck_…`로 먼저)
   - `shop.pay.api`(함수 주소)
   - `shop.pay.enabled: true`
   - `shop.seller`(판매자 정보)
   - `shop.shippingKrw`
6. 테스트 키로 결제·실패·취소·새로 고침·두 번 누르기를 시험한 뒤 `live_ck_…` / `live_sk_…`로 바꾸기

시험: 주소에 `?shoptest=1`을 붙이면 서버·결제 없이 이 기기에서만 주문 흐름을 흉내 내요. 예시 작품도 살 수 있어요.

앱(Capacitor)에서 결제할 때:
- 카드사·간편결제 앱으로 넘어갔다가 돌아오는 처리가 필요해요.
- Android는 `intent://` 주소를 앱이 열어 줘야 하고, iOS는 `LSApplicationQueriesSchemes`에 카드 앱 스킴을 넣어야 해요.
- 토스페이먼츠 '웹뷰 연동' 가이드대로 껍데기를 한 번 고쳐서 다시 내야 해요.

해외 구매자:
- 지금은 국내 배송·원화 카드 결제만 받아요. 해외는 문의로 받아요.
- 토스는 PayPal(해외 간편결제, USD)도 지원해요. 해외 카드·배송·통관을 열 때 따로 붙여요.

## 판매 전에 할 일

- 작가와 위탁·판매 계약(수수료, 가격 결정권, 정산 주기)
- 통신판매업 신고
- 판매자 정보 표시(`shop.seller`)
- 약관 '작품 구매' 조항 확정(법률 검토)
- 청약철회:
  - 전자상거래법상 받은 날부터 **7일 안에 청약철회가 원칙**이에요.
  - 예외(주문 제작, 고객 책임의 훼손 등)는 법에서 정한 경우만 돼요. '미술품이라 반품 불가'처럼 일률적으로 막을 수 없으니 법률 검토가 필요해요.
- 배송: 미술품 전문 운송, 보험, 파손 시 처리
- 개인정보:
  - 주문·배송 정보를 수집하는 항목과 보관 기간을 정해요.
  - 운송 업체에 제공하는 것을 개인정보처리방침에 반영해요.

## 문의 (결제를 켜지 않은 작품·해외 구매자)

- 지금은 **문의 방식**이다. `config.shop.inquiryEmail`에 받는 메일 주소를 넣으면, 문의를 보낼 때 관람객의 메일 앱이 작품 정보가 채워진 채로 열린다.
- 메일 주소가 비어 있으면 화면에 '문의 창구 준비 중'이 뜬다.
- **실물 작품은 애플·구글 인앱결제 대상이 아니다**(실물 상품). 나중에 앱 안에서도 일반 결제(토스페이먼츠·포트원·Stripe)를 붙일 수 있다.
  - 순서: 서버에 주문 표를 만들고 → 결제 → 재고·상태를 `reserved`/`sold`로 바꾼다.
- 디지털 작품(파일)은 앱 안에서 팔면 인앱결제 대상이 된다. 그래서 지금은 종류에서 뺐다.
